# 模板：routing（路由型）

## 适用场景

- 选它：领域多、想按需加载省上下文（入口只读路由表，任务相关才读领域文件）；与 Anthropic just-in-time 上下文方向一致。
- 不选它：想要"每个任务开始全量读上下文"的固定纪律（用 memory-bank）；只关心决策记录（用 decision-log）。

## 结构规范

```
AGENTS.md          # 入口：Memory 节指向 MEMORY.md
MEMORY.md          # 路由：一行一领域 + 头部写入纪律
.agents/memories/  # 领域记忆文件，如 python-rag.md、vue-frontend.md、terminology.md
```

### AGENTS.md 的 Memory 节

```markdown
## Memory

- 开始任务前先读 `MEMORY.md`（记忆路由），按其中"何时读"列按需读取 `.agents/memories/` 下的领域文件。
- 产生值得长期保留的决策、结论或踩坑时，按 `MEMORY.md` 头部维护规则写入对应领域文件。
```

### MEMORY.md 模板

```markdown
# MEMORY.md — 记忆路由

> **维护规则（写入记忆前必读）**
> 1. 一行一文件：每个领域文件必须登记到下表；"一句话范围"不超过一句话。
> 2. 领域文件放 `.agents/memories/`，kebab-case 命名（如 python-rag.md、terminology.md）；一个文件 = 一个领域。
> 3. 开新领域文件的门槛：同一主题已累积 ≥ 3 条持久记忆；不满足就并入最相近的现有领域文件。
> 4. 只记决策、理由、踩坑与最终选择；不记流水账，不复述代码或提交记录里直接可见的信息。
> 5. 领域文件无路由行即为孤儿：补登记或并入相近文件；删除文件必须同步删路由行。

| 领域文件 | 一句话范围 | 何时读 |
| --- | --- | --- |
```

路由表不为演示造示例行：全新项目留空；`.agents/memories/` 已有文件时登记后交付，不留孤儿。

### 领域文件（懒创建）

初始化不创建任何领域文件；某领域第一条记忆出现时才创建并登记路由行。文件内部格式随领域自定（术语表用表格、决策记录用小节均可），条目建议带日期便于回溯，文件头一行写明领域，例如 `# Python RAG 开发记忆`。

## 初始化

1. `mkdir -p .agents/memories/`（已存在则跳过，不视为异常）。
2. `MEMORY.md` 不存在时按模板生成；**已存在则绝不覆盖**，缺维护规则头时把它作为建议报告给用户，不擅自改。
3. `MEMORY.md` 新建后立即扫描 `.agents/memories/*.md`：已有文件就为每个补路由行（"一句话范围"从文件头或文件名提炼，拿不准问用户），不得交付孤儿；没有文件则路由表留空。
4. `AGENTS.md`：不存在则创建含 Memory 节的最小文件；存在但没有指向 `MEMORY.md` 的引用则追加 Memory 节；已有引用（不限章节标题）则不动。

## 模板特有审计项

- 双向一致：`.agents/memories/*.md` 每个文件在路由表有行；每条路由行指向存在的文件。
- 路由行质量：三列齐全（领域文件 / 一句话范围 / 何时读），"一句话范围"未超一句。

## 模板自检

- [ ] `MEMORY.md` 存在，维护规则五条齐全，路由表三列表头就位（全新项目为空表）
- [ ] `AGENTS.md` 已含指向 `MEMORY.md` 的引用且无重复
- [ ] `.agents/memories/` 目录存在，已有文件均已登记路由行，未创建空壳领域文件
